# `desc.mrq` format (moresampler f0 cache)

Status: **verified** against Kanru Hua's official reader/writer (`mrq.c`/`mrq.h`, BSD-style
license) and parsed successfully against a real `desc.mrq` from the local corpus.

moresampler (the UTAU resampler by Kanru Hua) keeps one `desc.mrq` per voice folder next to the
wav files. It caches only **f0** (no volume) so that re-synthesis does not re-run pitch
estimation. Hand-edited entries are respected; auto-generated entries are refreshed when stale.

## Binary layout (v2, little-endian, no padding, no alignment)

Header (12 bytes):

| Offset | Type | Field |
| --- | --- | --- |
| 0x00 | `char[4]` | magic `"mrq "` — **includes the trailing space** (`6D 72 71 20`) |
| 0x04 | `int32` | format version, `2` (`MRQ_VERSION`) |
| 0x08 | `int32` | entry count (may include zero-length "deleted" entries) |

Entry (v2):

| Type | Field | Notes |
| --- | --- | --- |
| `int32` | `nfilename` | length of the filename in **UTF-16 code units**, not bytes (`fread(name, 2, n, f)`) |
| `uint16[n]` | `filename` | UTF-16, host-endian (LE on Windows), no BOM, no NUL terminator. Bare wav filename, e.g. `_かきくけこ.wav` |
| `int32` | `size` | byte length of the data trunk **after this int**: v2 = `20 + 4*nf0`, v1 = `12 + 4*nf0`. Used to seek/skip |
| `int32` | `nf0` | number of f0 points |
| `int32` | `fs` | sample rate (44100 typically) |
| `int32` | `nhop` | samples between f0 points. `2^ceil(log2(fs * 0.005))` → 256 at 44.1k/48k, 512 at 96k |
| `float32[nf0]` | `f0` | Hz; `<= 0` (in practice `0.0`) = unvoiced |
| `int32` | `timestamp` | Unix time when the entry was generated |
| `int32` | `modified` | `0` = hand-edited (trusted); `>= 1` = version of moresampler that generated it. `524` = `0x20C` = 0.8.4 |

- v1 entries have no `timestamp`/`modified`; readers detect them with `size >= 20 + 4*nf0` and
  leave both fields as 0. A hand-made/mrq-tool entry also has `timestamp == 0` and is trusted
  forever.
- `entry_count` is **never decremented**; deleted entries keep a zero-length name and are skipped.
  `mrq_defragment()` compacts them. Lookup is a linear `wcscmp` scan.
- moresampler writes f0 comparison-faithful to its LLSM analysis; no amplitude. When converting to
  `frq`, amplitude must be sourced elsewhere (frqeditor reads it from the wav).

## Regeneration rules (0.8.x)

Controlled by `auto-update-llsm-mrq` in `moreconfig.txt` (default on):

- `.llsm` data versions: accepted 520..599, current 524. Newer-but-incompatible (>599): abort to
  protect the file; older: regenerate.
- `timestamp != 0 && wav_mtime > timestamp` → discard f0 and re-estimate.
- `timestamp != 0 && modified != 0 && modified <= 519` → generated by deprecated version → re-estimate.
- `timestamp == 0` → trust the entry (hand edits survive).
- `load-frq off/on/strict` controls whether `.frq` data is used to fill/correct unvoiced frames.

## Filename keys and code pages

`mrq.h` documents the design: UTAU passes **8-bit Shift-JIS filenames** to resamplers, and the
system's 8-bit command-line conversion interprets those bytes with the machine's code page on the
way to the resampler; moresampler stores the resulting UTF-16 filename as the entry key. The key is
therefore simply the wav filename as the running environment sees it: mojibake for non-ASCII names
on a non-Shift-JIS system is expected, not an error. The corpus carries this CP932→CP936 fallout
(see `frame-conventions.md`).

KiraFrqGen keys entries on the bare wav filename **as stored on the filesystem**, verbatim. The
only addition is the opt-in sharing mode: on a machine whose code page is not 932 it also writes
the Japanese-code-page name of the same wav, so a shared `desc.mrq` works in the Japanese region.

## Corrections to the original reverse-engineering draft

The draft was nearly right. Fixes:

1. `entry_name_length` counts UTF-16 **code units**, not bytes.
2. `offset_to_next` is the remaining entry length **from the end of that int** (includes the
   timestamp/modified in v2), i.e. v2: `20 + 4*nf0`.
3. `modified` is not just a version: `0` means hand-edited; `524` (0x20C) is written by 0.8.4.
4. f0 `<= 0` means unvoiced; no volume is stored.
5. There is no `time_t`-on-disk subtlety: it's a plain int32 Unix timestamp.

## Local verification

`.local/verify_formats.py` parsed one corpus `desc.mrq` (11,430 bytes):

- magic `mrq `, version 2, 3 entries, final offset == file size.
- entry names decode as UTF-16LE (`_ああいあうえあA2.wav`, ...), `size == 20 + 4*nf0`, `fs=44100`,
  `nhop=256`, `modified=524`, timestamps = Unix time of generation.
- Unvoiced frames are `0.0f`; f0 maxima ~117–128 Hz (A2 folder).
